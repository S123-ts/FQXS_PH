# 番茄小说排行榜爬虫（FQXS）

Spring Boot 3.5 + OkHttp 抓取 `fanqienovel.com` 排行榜（男/女频 × 阅读榜/新书榜，37 个子分类），
H2 文件库落库，无框架单页展示与筛选。

> 使用前请先读文末的**免责声明**。

## 运行

```bash
./mvnw -B spring-boot:run
# 打开 http://localhost:8080 → 会先跳到登录页
```

数据落在 `data/fqxs.mv.db`（已 gitignore），启动自动建表并幂等回填历史数据。

### 登录

全站（含所有 `/api/**`）都要先登录，默认凭据写在 `application.yml` 的 `app.auth` 下：
**账号 `admin`，口令 `admin`**。

> **`admin` / `admin` 只是仓库里的占位默认值**：本仓库公开，个人口令不随仓库公开。
> 本机或服务器要用自己的口令，设 `APP_LOGIN_USER` / `APP_LOGIN_PASSWORD` 环境变量覆盖（后者优先）；
> 公网部署必须覆盖并把默认值留空——留空是 fail-closed（登录接口 403、全站拒绝访问）。

| 行为 | 规则 |
|---|---|
| 会话 | 2 小时无操作失效；可随时「退出」 |
| 失败限流 | 同一来源连续 5 次失败锁定 5 分钟（第 6 次起回 429） |
| 反代后面 | 设 `APP_AUTH_TRUST_FORWARDED=true`，并让反代**覆盖** `X-Forwarded-For`，否则按 IP 限流会退化成「一次锁定全站」 |

## 功能

| 模块 | 说明 |
|---|---|
| **榜单抓取** | 男/女频 × 阅读榜/新书榜 × 37 个子分类；「一键获取全部」每分类抓 70 本，掉榜的书自动清理 |
| **榜单浏览** | 单页无框架，切榜直接读库不重抓；每页 10 本，分类榜与「全部」视图通用 |
| **筛选** | 字数（默认 100 万以上）、状态（默认连载中）、作者性别（默认男作者）、作者评分（默认 9.0），四项都下推 SQL |
| **「新」标识** | 书名后的「新」表示 7 天内首次进榜；判据是入库时间而非最近抓取时间，掉榜后重新上榜重新计时 |
| **拉黑 / 关注** | 按 bookId 全行联动，拉黑默认隐藏、关注默认保留；批量操作串行执行并显示进度，拉黑需二次确认、6 秒内可撤销 |
| **作者信息** | 第三方详情接口补齐作者性别与评分，后台按热度每小时补 60 本，性别只取一次、评分 5 天后刷新 |
| **拉取频道** | 第一行的「全部 / 男频 / 女频」决定后端抓哪些分类，与「展示分类」是两件事——它不改当前列表看什么 |

两点使用时的预期管理：

- **筛选默认值会把列表筛得很空**（评分 9.0 + 字数 100 万 + 连载中 + 男作者四项叠加）。这是默认值的代价，
  不是抓取故障；要看全量把评分清空、字数与状态切「全部」。
- **刚整榜重抓后作者性别大多是未知**，默认视图可能一本书都没有，切「全部」即可。
  接口给不出性别时按书籍频道兜底（男频书记男、女频书记女），这是产品取舍：男频里的女作者会被记成男。

## Legado 书源（可选）

把本服务当书源接进「阅读」App：

1. 手机与电脑在同一局域网，`bookSourceUrl` 填 `http://<电脑局域网IP>:8080`；
2. 书源骨架里 `bookUrl` / `tocUrl` 直接取服务端返回的完整地址，`searchUrl` 由书源规则发出、需在规则里显式带 token；
3. 四个只读端点：`/api/bs/search`（搜本地库）、`/api/bs/info`、`/api/bs/directory`、`/api/bs/content`。

搜索只覆盖**上过榜的书**——官方搜索带字节系动态签名风控，这是刻意的取舍。目录端点也只对本地库收录的书开放，
未收录回 `code=404`，不会为任意 bookId 触发上游请求。这组端点在登录门白名单里（阅读 App 没有会话），
所以**公网暴露必须**设置 `BOOK_SOURCE_TOKEN`，请求带 `?token=` 或 `X-Bs-Token`；留空只适合内网。

## 开发

```bash
./mvnw -B -o test        # 单元测试
./mvnw -B -o package     # 打包
```

改完 `static/**` 后建议跑一遍真实浏览器断言（记得先重新编译，`spring-boot:run` 从 `target/classes` 伺服）：

```bash
npm i                           # 一次性：playwright-core + typescript（都不进 Maven 构建）
npm run typecheck               # 前端静态类型（jsconfig.json + 各模块 // @ts-check）
node scripts/ui-smoke.mjs       # 主路径冒烟，默认打 http://localhost:8080
node scripts/ui-block-smoke.mjs # 拉黑与批量：confirm 态、计数、串行次数、撤销（写接口打桩，不写库）
```

两个脚本退出码非 0 即有回归。启动浏览器时都带 `--no-proxy-server`：冒烟目标是 localhost 或直连 IP，
跟随系统代理只会把请求甩给一个可能没在监听的端口，报 `ERR_CONNECTION_RESET`，而同一时刻 `curl` 是通的——
那种组合极易把「代理挂了」误判成「服务挂了」。

## 数据模型

- `novel_rank`：`(category_code, rank_type, book_id)` 组合唯一；阅读榜/新书榜各自成快照，
  切榜直接读库、无需重抓；`is_blocked`（拉黑）与 `is_watched`（关注）按 bookId 全行联动。
- `author_meta`：作者 / 性别 / 评分的长期缓存，主键就是 `book_id`。**跟书走、不跟榜走**——
  榜单行掉榜被清理时不连带丢掉，书重新上榜直接命中，不再重复请求第三方详情接口。
- `app_log` / `api_log` / `third_party_log`：程序日志、接口日志、第三方线路尝试日志落库，
  三张表都带 `book_id`，生命周期跟随书；`/records` 页的数据源就是它们（文件日志仍然保留）。
- `app_config`：运行时配置——榜单类型、展示分类、拉取频道（全部 / 男频 / 女频）。

数据库结构由 Flyway 迁移管理（`src/main/resources/db/migration`），`ddl-auto=none`，
应用永不改库结构；已应用的迁移文件不许再改内容（checksum）。
