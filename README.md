# 番茄小说排行榜爬虫（FQXS）

Spring Boot 3.5 + OkHttp 抓取 `fanqienovel.com` 排行榜（男/女频 × 阅读榜/新书榜，37 个子分类），
H2 文件库落库，无框架单页展示与筛选。

> 使用前请先读文末的**免责声明**。

## 运行

```bash
./mvnw -B spring-boot:run
# 打开 http://localhost:8080 → 会先跳到登录页
```

数据落在 `data/fqxs.mv.db`（已 gitignore），启动自动建表并幂等回填历史数据。

### 登录

全站（含所有 `/api/**`、`/swagger-ui.html`）都要先登录，默认凭据写在
`application.yml` 的 `app.auth` 下：**账号 `admin`，口令 `admin`**。

> **`admin` / `admin` 只是仓库里的占位默认值**：本仓库公开，个人口令不随仓库公开。
> 本机或服务器要用自己的口令，设 `APP_LOGIN_USER` / `APP_LOGIN_PASSWORD` 环境变量覆盖（后者优先）；
> 公网部署必须覆盖并把默认值留空——留空是 fail-closed（登录接口 403、全站拒绝访问）。

| 行为 | 规则 |
|---|---|
| 会话 | 2 小时无操作失效；口令页可随时「退出」 |
| 失败限流 | 同一来源连续 5 次失败锁定 5 分钟（第 6 次起回 429） |
| 改凭据 | 设环境变量 `APP_LOGIN_USER` / `APP_LOGIN_PASSWORD`（后者优先）；`application.yml` 默认值保持 `admin`/`admin` 不动（git 里只允许这一组） |
| 反代后面 | 设 `APP_AUTH_TRUST_FORWARDED=true`，并让反代**覆盖** `X-Forwarded-For`，否则按 IP 限流会退化成「一次锁定全站」 |

## AI 文判定

> **每天最多 500 次模型调用**（`ai.detect.daily-call-limit`，环境变量 `AI_DAILY_CALL_LIMIT`，`0` = 不限）。
> 一次真实出网调用算一次，超了接口回 429 并提示剩余策略；这个上限挡的是「循环点按钮把免费额度烧完」，
> 不是精确计费（计数在调用前读、用量在调用后异步落库，最后几次可能略超）。

### 一、在页面里配置（推荐，30 秒）

1. 打开页面 → 工具栏点 **「🔑 API 密钥」**；
2. 把 Key 粘到对应引擎的输入框 → 点 **「保存」**；
3. 立即生效，无需重启：**「AI引擎」** 下拉马上出现该引擎，「🧪 校验选中 / 🧪 AI 初筛」随即可用。

内置三个引擎（GLM / 千帆 / 硅基流动）填任意一个就能开始判定，不需要全填；也可以在面板底部
**「＋ 添加自定义引擎」**接入任意 OpenAI 兼容服务（base_url + 模型名）。留空表示不修改；点「清除」再保存即可删除。
**未配置的引擎默认收起**成一行（只显示名称、状态与「配置」按钮），点「配置」展开表单，再点「收起」折叠——
面板打开时先看到的是已经配好的那些。

**换模型**：GLM、千帆与 Qwen 每行下方是**型号多选标签**，勾选即保存、立即生效。可以勾多个：
每次判定会在勾选的型号里**随机取一个**（分摊额度与限流）；勾选池里的任一型号判过某本书就算判过，
不会重复烧额度。把勾选池换成全新型号后，旧结论不再复用，会按新池重新判定（面板的「待判」数量会随之变化），
旧型号的结论仍保留在明细表里可追溯。

每行还有一个 **「测试」** 按钮：真实发一条样例，同时验证连通性和输出契约（模型是否肯回
`{"ai_probability": N}`）。通不过测试的模型在批量判定里一定会失败。

**试读章节会自动跳过**：番茄未登录时只有每本书前 10 章是完整正文，第 11 章起是 VIP 试读（一百多字）。
取样会按实际正文长度过滤，样本不足时回退扫描前几章；仍然凑不够会直接报错，不会拿试读片段硬判。

### 额度与有效期能看到什么

面板每个引擎下方有一行「额度」，按平台**是否真的开放了接口**区分，不编造数字：

| 引擎 | 能查到什么 | 有效期 |
| --- | --- | --- |
| 硅基流动 Qwen | 真实余额：赠送 / 充值 / 合计（`GET /v1/user/info`） | 接口不返回到期时间，标注「以控制台为准」 |
| 智谱 GLM | **没有余额接口**（2026-10-21 实测 `/api/paas/v4/account/balance`、`/balance`、`/user/info`、`/usage` 全 404）；只标注当前型号是免费档还是付费档 | 免费档无到期日；付费余额到控制台看 |

选到付费型号（`GLM-5.3-Flash`、`GLM-4.7` 等）时，额度行会显示红色 **「付费模型」** 徽章并按 token 计费提示，
避免误以为还在免费档跑批量。

### 三、接入自己的 API（任意 OpenAI 兼容服务）

面板底部「＋ 添加自定义引擎」：填名称、接口地址、模型名即可。地址可以是裸域名、带 `/v1` 或完整的
`/chat/completions`，服务端会归一；只允许 https（本机 Ollama 可用 `http://localhost`）。添加后回到列表填 Key → 保存。
自定义引擎会自动进入「AI引擎」下拉与批量初筛的熔断候选集；内置引擎不可删除，只能停用。

**智谱 GLM（推荐首选）**

1. 手机号注册并完成实名（个人认证即可）；
2. 右上角头像 →「API 密钥」→「新建密钥」；
3. 复制生成的 Key（形如 `1a2b3c4d.5e6f7g8h`），直接粘进面板的 GLM 一行；
4. 该模型在开放平台是免费档，日常初筛不会产生费用。

**硅基流动 Qwen**

1. 注册后完成实名；
2. 左侧「API 密钥」→ 新建，复制 `sk-...`；
3. 面板里粘到 Qwen 一行；免费模型列表会调整，若报「模型不存在」，在控制台「模型广场」搜 `Qwen2.5-7B-Instruct` 确认当前免费标识。

**千帆 ERNIE（可选）**

1. 打开千帆控制台完成实名；
2. 先到「在线服务」开通 ERNIE 系列，再在「API 密钥」新建；
3. 粘到 ERNIE 一行；未开通在线服务时接口会返回 `invalid_model`（不是 Key 错）。

### 四、密钥安全规则（硬性）

- **只存本机**：面板保存的 Key 写入 `data/ai-keys.properties`，`data/` 已在 `.gitignore` 中，
  **永远不会被提交到 Git / GitHub**。
- **不进代码、不进配置样例**：不要把 Key 写进 `application.yml`、README、测试用例、截图或 issue。
- **不回显明文**：`GET /api/ai/keys` 只返回掩码（前 4 + 后 4），后端日志不打印 Key。
- **写操作要令牌**：保存密钥是 POST，受 `X-Rank-Token` 保护（与抓取接口同一套）。
- **环境变量优先**：`GLM_API_KEY` / `QIANFAN_API_KEY` / `QWEN_API_KEY` 已设置时以环境变量为准，
  面板值不会覆盖它们。
- **泄露处置**：一旦 Key 误入提交或截图，立刻到平台控制台吊销并重建；`data/` 下的文件不要外发。

### 五、备选：环境变量 / ai-keys.bat

不想用页面面板时，可以复制 `ai-keys.bat.example` 为 `ai-keys.bat`（同样已 gitignore）填写 Key，
`start.bat` 启动时会自动加载；或直接在系统环境变量里设置 Key 后重启应用。

### 六、用法

- **AI 引擎下拉**：列出所有已配 Key 的引擎；配了两个以上时多一项 **🎲 随机（自动分摊）**，
  每次挑没判过这本书的引擎。
- **🧪 校验选中**：先勾选书（单选或多选，任何视图都有方框），再用所选引擎逐本判定（**3 本同时跑**，边判边亮徽章）；勾「重判」可忽略已有结论重跑。
  同一本书的同一个引擎仍会排队（它有一份逐章进度要推进），不同书、不同引擎互不干涉。
- **点模型名重跑**：行内结论徽章（如「GLM 80%」）本身是按钮，点一下用该引擎 + 当前取样规则重跑这本书，结果记进「详情」的校验流水。
- **「详情」**：行内「更多」→「详情」，每张型号卡给**两个口径**——卡头是**最近一次**结论（逐章命中优先，否则最新），
  下面一行「综合 x%（n 轮 / m 章）」是**按章数加权**的平均值：每轮按它实际看了几章计权重，只推进度与调用失败的轮次不计入。
  有过命中时后面跟红字「含 N 次 AI 命中」——平均值不许把一次确凿命中冲淡。卡内「校验记录」列最近 100 轮（含失败行与原因）。
- **🧪 AI 初筛**：批量跑该引擎未判过的书，**一次点击只判一批**（默认 5 本，单次上限 30 本），
  结束提示「还剩 N 本未判，可再点一次继续」；不再自动续批、页面加载也不会自动跑。
  本次点击内连续失败（坏批 / 鉴权 / 限流）会换一个可用引擎重试一次。
- **取样**：只有三档固定配方，章数不可调 ——
  ① **前 10 章 · 官网**（默认）：全书前 10 章走官方 SSR，**正文落库**（`novel_chapter`），同一本书第二次起零上游请求；
  ② **最新 10 章 · 第三方**：全书最后 10 章走会员正文通道；
  ③ **随机 2×5 章 · 第三方**：第 11 章起随机抽两段、每段 5 章，互不重叠，硬性不碰前 10 章（全书不足 20 章会直接报错）。
  第三方线路不可用时，后两档**直接报错**而不是偷偷改取前 10 章——否则记录的取样档位会说谎。
  「不可用」指**整份线路清单都没活线**：`ai.detect.third-party-base-urls`（逗号分隔，环境变量
  `THIRD_PARTY_BASE_URLS`）是按顺序尝试的清单，某条挂了只冷却它自己并自动换下一条
  （公共线目前只剩 `fq-book.netsite.cc` 一家可用，清单机制是给自建的 FQWeb/PyFQWeb 实例留位）。
  同一套线路还给目录提供了第二条路：官方目录被风控时 `/api/bs/directory` 自动改用它。
  **正文 < 500 字的试读章节会被跳过**，样本不足直接报错，不会拿试读硬判。
- **失败日志**：模型调用失败会把原因与上游返回片段写进 `ai_engine_fault`，同一引擎连续 3 次失败自动停用 1 小时（`fault-suspend-hours` 可调，成功即清零、到期自动恢复）；
  两页页头有「审查记录 / 失败日志」tab 可互切，也可直接开 `/faults`。失败明细按类型着色并可按类型筛选
  （限流 / 鉴权失败 / 上游故障 / 网络超时 / 空响应 / 解析失败），原因与上游片段折叠两行、点击展开；
  停用中的引擎在页首黄条列出，可手动解除。
- **🌙 后台自动校验**：应用起来后有一条守护线程（`ai-verify-backfill`）按热度序自动推进——**每 10 分钟一轮，每轮让每个已启用的引擎各查一本的一章**，直到该书前 10 章被该引擎的每个「家族代表」型号查完
  （同一模型的不同包装——上下文长度 / 日期快照 / `-flash` 变体——只跑一个代表，省下的额度换产量；真正不同代、不同规模的模型仍各跑各的）。
  节拍与开关是 `ai-verify-backfill-per-hour`(6) / `ai-verify-backfill-enabled`(true)，均可用环境变量覆盖；节拍按 60 轮/小时钳制。
  免费渠道的日额度有限（三家引擎 ≈ 432 次/天 vs `daily-call-limit` 500），页面手动校验与后台**共用同一份额度**：
  额度到顶或上游线路冷却时后台当轮收尾、不硬撞；页面正在手动校验同一本同一引擎时后台让路（不算失败）；
  同一轮连着失败 3 次就歇 10 分钟，引擎级的「连续失败停用 1 小时」仍由熔断器负责。
- **📜 审查记录**：`/records` 一页看三块 —— **正在 AI 审查**（进行中的判定 + 已用时）、
  **正常拉取章节**（每本书的章数 / 字数 / 最新章号 / 最近拉取 / 残留 PUA）、
  **判定结果**（最近的判定流水：结论徽章、概率、**查的是第几章**、类型、理由；标题行可按书名检索，
  结论 chips 可与检索叠加筛选，计数显示「命中 / 总数」；失败行的「失败」徽标可直接跳到失败日志）。
  顶部三项 KPI（窗口内拉取 / 正在审查 / 窗口内结论），3 秒自动刷新（标签页在后台时暂停，检索与筛选不会被刷新冲掉），
  时间窗口 6 小时到 30 天可切。首页动作行的「📜 审查记录」即入口，两页页头 tab 互切。
- **逐章校验**：每本书后面按已配置的引擎各有一枚按钮（GLM / ERNIE / QW），**点一次按当前取样规则查完一批章节**
  （默认**前 10 章**），不再一章一点：按钮实时显示 `校验中 n/总数`，一批查完只弹一条提示。
  **同一模型同一章节不重复校验**，命中 AI 也会继续把剩余章节查完，每一轮都写进「详情 → 校验记录」。
  型号由服务端在型号池里随机挑（摊额度），所以一批可能跨两三个型号；池内所有型号都查完按钮才置灰
  （按钮上的 `n/总数` 就是池内总进度，再点一次继续下一批）。
- **作者性别与评分**：筛选栏「作者」默认只看**男作者**（可切女作者 / 未知 / 全部），行内在作者名后显示第三方评分（★ 8.6）。
  **评分筛选**是作者组右侧的输入框（0–10，默认 **9.0**，留空=不筛；改 9.5 下次打开仍是 9.5，记在浏览器里），
  与字数（默认 **100 万以上**）、状态（默认 **连载中**）一起下推 SQL。三者叠加会把列表筛得很空（评分还在慢慢补），
  默认视图几乎为空是这三个默认值的代价，不是抓取故障；要看全量把评分清空、字数/状态切「全部」。
  刚整榜重抓后库里性别大多还是**未知**，默认视图可能是 0 条——这是「默认只看男作者」的已知代价（不是缺陷，也别改它），要看全量就切「全部」。
  数据来自第三方书籍详情接口（`author_info.profile_gender` 0=女 / 1=男 / 2=未知，`score` 0–10；顶层 `gender` 是书籍频道，不能当作者性别），**该线路容量很小**，
  接口给不出性别时**按书籍频道兜底**（男频书记男、女频书记女），掉榜的书无从兜底才显示「未知」——这条兜底是产品取舍：
  男频里的女作者会被记成男，追查单本来源可看后台日志里的「（按书籍频道兜底）」标记。
  所以补数是有节拍的：**后台补齐线程**默认每小时 60 本，按总榜热度从高到低逐本推进，队列只排「拉取频道」那一档（见下条）；
  工具栏里的「补作者信息」按钮是应急用，每次只取 **5 本**、严格串行。性别只取一次，评分默认 5 天后刷新（`ai.detect.rating-refresh-days`）。
  作者信息存在 `author_meta` 表里**跟书走**，书本掉榜被清理不会连带丢掉，重新上榜直接命中、不再重复请求线路。
  还没轮到的书归入「未知」。
- **拉取频道**：第一行「拉取：全部 / 男频 / 女频」决定**后端去拉哪些分类**（以及补齐队列排哪一档书），
  和「展示分类」是两件事——它**不改当前列表看什么**，切完也不会立刻刷新列表；改的是下一轮抓取与补齐的对象。
  默认「全部」。切换后要等后台补齐的下一轮（最长约 1 小时）才体现在队列上，想立刻生效重启服务。
- **每页与抓取量**：列表每页默认 **10 本**；「一键获取全部」每个分类抓 **70 本**（上游榜单共 100 本），掉榜清理按 70 本这个口径执行。
- **「新」标识**：书名后的**「新」**表示这本书**7 天内才第一次进榜**（判据是入库时间，不是最近一次抓取时间——
  所以每天刷新榜单它也不会一直亮）。掉榜后重新上榜会重新计时。分类榜和「全部」视图都有。
- **批量拉黑 / 批量恢复**：每行行首有勾选框（所有视图都有）；桌面批量条未选中时隐藏，手机在有选择时浮在分页条上方，可**全选本页**后批量拉黑或恢复；
  串行逐本执行并在条内显示 `处理中 n/总数`，完成后统一给出成功与失败条数。选择只作用于当前页，翻页或换分类即清空。
- **拉黑要确认**：第一次点「拉黑」只会变成「确认拉黑?」（3 秒内不点自动复位），再点一次才真正生效；
  成功后 6 秒内可点提示条上的「**撤销**」把这本书恢复回来。恢复方向是安全的，一次点击即生效。
- 每个引擎的结论独立入库、独立展示，可同屏对照；所有 Key 都不配也能正常用榜单功能，
  判定接口会返回 400 并说明缺哪个。

### 七、提示词变体池

判定提示词不写死在代码里：`ai_prompt` 表内置 8 个变体（P1 总判别、P2 特征分解、P5 轻量快筛、
P7 中文八股、P8 语法毛刺等），默认每次判定从启用池里**按权重随机取一条**，结论记录 `prompt_id` 可追溯。
想让结论可复现，设 `ai.detect.prompt-strategy=fixed` 并指定 `default-prompt`。

### 前端冒烟回归

改完 `static/**` 后（记得重新编译，`spring-boot:run` 从 `target/classes` 伺服），可以跑一遍真实浏览器断言：

```bash
npm i                           # 一次性：playwright-core + typescript（都不进 Maven 构建）
npm run typecheck               # 前端静态类型（jsconfig.json + 各模块 // @ts-check）
node scripts/ui-smoke.mjs       # 主路径冒烟，默认打 http://localhost:8080
node scripts/ui-block-smoke.mjs # 拉黑与批量：confirm 态、计数、串行次数、撤销（写接口打桩，不写库）
```

`ui-smoke.mjs` 共 64 项断言：首屏出书、无未捕获异常、默认按男作者筛选、改每页条数 / 翻页 / 设置面板、密钥面板空保存即关、
宽屏单列、分页吸底与桌面吸顶、手机折叠摘要、失败日志页、审查记录页（入口跳转、出数据行、章节列写明第几章、
判定结果按书名检索与自动刷新保留、手机档无横向溢出、能进失败日志）、关注入口、键盘快捷键（j/k/x/Enter）、行内「更多」菜单；退出码非 0 即有回归。

`ui-block-smoke.mjs` 共 27 项断言，覆盖多选（所有视图）、全选本页、批量拉黑条数与串行请求次数、
拉黑二段确认（首点不发请求）、点别处复位、撤销回滚、关注一次点击生效与「只看关注」参数；
**block/unblock/watch/unwatch 的 POST 全被拦截并回成功信封**，所以它不会改动真实数据。
切榜、一键获取、AI 判定按钮仍需人工过一遍。

两个脚本启动浏览器时都带 `--no-proxy-server`：冒烟目标是 localhost 或直连 IP，跟随系统代理只会把请求
甩给一个可能没在监听的端口，报 `ERR_CONNECTION_RESET`，而同一时刻 `curl` 是通的——那种组合极易把
「代理挂了」误判成「服务挂了」。

## Legado 书源（可选）

把本服务当书源接进「阅读」App：

1. 手机与电脑在同一局域网，`bookSourceUrl` 填 `http://<电脑局域网IP>:8080`；
2. 书源骨架里 `bookUrl` / `tocUrl` 直接取服务端返回的完整地址，`searchUrl` 由书源规则发出、需在规则里显式带 token；
3. 四个只读端点：`/api/bs/search`（搜本地库）、`/api/bs/info`、`/api/bs/directory`、`/api/bs/content`。

搜索只覆盖**上过榜的书**——官方搜索带字节系动态签名风控，这是刻意的取舍。
目录端点也只对本地库收录的书开放，未收录回 `code=404`，不会为任意 bookId 触发上游请求。
这组端点在登录门白名单里（阅读 App 没有会话），所以**公网暴露必须**设置 `BOOK_SOURCE_TOKEN`
（或 `fqxs.book-source.token`），请求带 `?token=` 或 `X-Bs-Token`；留空只适合内网。
启用令牌后，服务端返回的 `bookUrl / tocUrl / chapterUrl` 会自动带 token；`searchUrl` 由书源规则发出，
需要在规则里显式加 `&token=…`（或改用 `bookSourceHeader`）。反代部署请让 Spring 信任转发头
（`server.forward-headers-strategy=framework`），否则返回的链接可能指向内网地址。

## 数据模型

- `novel_rank`：`(category_code, rank_type, book_id)` 组合唯一；阅读榜/新书榜各自成快照，
  切榜直接读库、无需重抓；主表 `ai_*` 存综合结论；`is_blocked`（拉黑）与 `is_watched`（关注）
  都按 bookId 全行联动，前者默认隐藏、后者默认留在列表里。
- `novel_ai_verdict`：逐引擎结论，`(book_id, engine, model)` 唯一，含
  `ai_flag / ai_score / reason / chapters_checked / prompt_id / sample_mode / sample_span`。
- `ai_engine`：引擎注册表（内置三家 + 用户自定义），`model_pool` 存勾选的型号池，
  `disable_until / disable_reason / consecutive_failures` 存自动停用状态。
- `ai_prompt`：提示词变体池（`enabled / poolable / weight`）。
- `ai_usage`：每次模型调用一行 token 明细，面板按日/按引擎聚合展示。
- `novel_ai_verdict_log`：每次判定的流水（append-only），`kind` 区分整本初筛 / 逐章一步 / 只推进度 / 手点重跑 / 调用失败；`sample_chapters` 记这一轮实际看了几章（详情里加权平均 AI 率的权重）。详情弹窗的「校验记录 N 轮」读它，每本保留最近 500 轮。
- `novel_chapter`：官方前 10 章的正文缓存（默认取样档），第二次起同一批章节零上游请求；只存官方，不存第三方。
- `ai_engine_fault`：调用失败留证（含上游返回片段），支撑自动停用与 `/faults` 查询页。
- `author_meta`：作者 / 性别 / 评分的长期缓存，主键就是 `book_id`。**跟书走、不跟榜走**——榜单行掉榜被清理时不连带丢掉，书重新上榜直接命中，不再重复请求第三方详情接口。
- `app_log` / `api_log` / `third_party_log`：程序日志、接口日志、第三方线路尝试日志落库，三张表都带 `book_id`，生命周期跟随书；`/records` 与 `/faults` 的数据源就是它们（文件日志仍然保留）。
- `app_config`：运行时配置——榜单类型、展示分类、拉取频道（全部 / 男频 / 女频）。

数据库结构由 Flyway 迁移管理（`src/main/resources/db/migration`，当前到 V21），`ddl-auto=none`，
应用永不改库结构；已应用的迁移文件不许再改内容（checksum）。
